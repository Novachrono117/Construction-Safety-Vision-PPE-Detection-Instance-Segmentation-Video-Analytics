## Nested same-class annotations (MANUAL DECISION)

**Decision: `REJECTED_FOR_AUTOMATIC_FILTERING`. All 2031 canonical annotations are retained and no automatic filter is applied.**

Phase 5B was asked to turn the phase 5A observation about the 76 annotations added since version 4 into a deterministic geometric rule. The experiment is preserved in [`fragment_rule_report.md`](fragment_rule_report.md) because a failed rule is useful evidence. It failed for a substantive reason, not a tuning one: containment inside an older same-class annotation is not evidence that an annotation is wrong. Annotations that appear as additions relative to version 4 include

* legitimate **instance splits** - one oversized `person` box covering two people replaced by one box per person;
* **coarse annotations replaced by several precise ones** - a single loose `vest_on_body` polygon replaced by the parts of the vest actually visible;
* **geometry refinements**;
* and genuinely degenerate slivers.

No evaluated rule separates the first three from the fourth, so automatic exclusion would risk deleting real ground truth. The project owner therefore rejected automatic filtering.

The 34 annotations the evaluated rule would have selected carry `action = KEEP` and `review_flag = NESTED_SAME_CLASS_CANDIDATE`. That flag is **descriptive**: it records that an annotation lies inside another of its own class. It does not assert that the annotation is wrong, and none has been established as a fragment by manual review.
